# Manual Evaluation Cases

这个文件定义 v1 的人工复核场景。它不是 benchmark，也不是自动测试脚本，而是每次修改 skill 后都应该重新检查的一组固定案例。

## Acceptance Criteria

每个案例都按这 4 项判断：

- 术语一致性
- 文风贴合度
- AI 痕迹降低
- 无虚构内容

## Cases

### Case 1: 只有草稿

输入：

- 只有待润色草稿。
- 没有课程材料。
- 没有过往样本。

期望：

- 只做保守润色。
- 不假装知道用户风格。
- 不引入不存在的术语偏好。

### Case 2: 草稿加课程摘录

输入：

- 草稿。
- 课程材料摘录或 assignment brief。

期望：

- 优先统一专业术语。
- 不把准确术语替换成更通俗但不精确的表达。
- 文风保持保守，不凭空个性化。

### Case 3: 草稿加过往样本

输入：

- 草稿。
- 至少一份用户过往写作样本。

期望：

- 在不改事实的前提下，明显贴近样本的段落节奏、语气和连接习惯。
- 不机械照搬样本内容。

### Case 4: 术语材料与样本冲突

输入：

- 草稿。
- 课程术语材料。
- 用户样本，其中某些词汇和课程术语冲突。

期望：

- 词汇服从课程术语。
- 语气和段落推进服从用户样本。
- 明显避免错误术语被样本“带偏”。

### Case 5: 中文作业与英文材料混合

输入：

- 中文草稿。
- 英文课程材料或英文术语清单。

期望：

- 保留必要的核心英文术语。
- 不做生硬全中文替换。
- 整体语言仍然自然可读。

### Case 6: 用户要求“更像真人”

输入：

- 草稿。
- 用户明确要求减少 AI 感、增加真人感。

期望：

- 明显压低模板化和空话。
- 句式与节奏更自然。
- 不能凭空加入个人经历、课堂记忆、假引用或假案例。

### Case 7: 用户只上传 PDF

输入：

- 只有 PDF 或图片文件。
- 没有摘录文本。

期望：

- 明确拒绝把文件处理当作 skill 内建能力。
- 请求用户提供文本摘录、转写文本或关键片段。
- 不假装已经读过文件内容。
